## 相等战损与成长证明

第二版仅增加相等战损观察及现有成长上界查询，没有删除分支。上述开放两瓶额度的4896次访问中，相等战损次数为0；观察到的Smart梯度成员也为0。因此，本根该阶段不支持用相等剪枝取得额外收益。这个结论不推广到其他根或其他搜索阶段。

成长HP让步额度为零，仍不能忽略相等战损下的成长次数。原比较顺序以及药水政策、原始战损和回合的细则保持。进一步复核了以下可达性区别：

- 禁忌魔典的原生Power在战后增加删牌奖励，模拟记录长期资源和成长；它不要求`DeckVersion`。但它的远古稀有度被普通`CardFactory.FilterForCombat`排除。认证表中存在其类型，不证明随机生成可达；初始持有、复制、回收仍需检查。
- HandOfGreed、Royalties的原生`CanBeGeneratedInCombat=false`；沿用同版本Feed、NotYet、Alchemize、TheHunt的普通生成过滤证据。不能把这些来源描述成正常随机生成可达。
- 遗传算法、巨镰可作为临时牌存在，永久成长须有`DeckVersion`关联；原生分别强化当前牌与牌组版本，模拟只在存在牌组版本时计成长。不能把临时战内强化当永久收益。
- 变牌、复制、待返回牌、消耗堆取回、重复执行、附魔以及回调，仍需证明它们保留或创建牌组关联的准确行为。初始成长目标和启发式机会次数不是总收益上界。

本次没有创建通用“无剩余成长”证书，也没有将回复认证表直接当成长认证表。普通随机生成、初始持有和复制/回收应逐项正向证明；未知机制继续保留搜索。

## 更严格的剪枝合同

可以沿用现有入口发展统一结果界，但新增消费者先满足以下合同：

1. 见证是当前调用方实际保留的完整、合规胜利，且调用方的原比较器只用更好的结果替换它。直接Smart审计和精确用药合同单独处理；不能用任意跨成员标量替代这些条件。
2. 分支从自身拥有的完整状态计算现有`ComponentHealingUpperBound`和`StrategicHpLowerBound`。已有再生、合法剩余药水、生命上限/当前生命变化、条件战后回复与复活资源按原语义处理；未知返回未知。
3. 在整个有效成长HP额度为零、没有更高优先级目标时，严格更差的战略战损已有安全合同。相等战损须另有剩余成长计数、原始战损、药水成本/次数和回合的保守界，并同时满足最终与协调器替换规则；不能只改成`>=`。
4. 成长上界必须覆盖全部可达来源、重复和回收；有限回复不证明有限成长，初始机会目标不证明全局次数。证明失败保留原搜索。
5. 不修改Smart资格、强制/禁药、成长、遗物、追回、保命和首领政策；不修改评分、预算、Beam入队或排名边界。完整胜利回退必须保留。先测能新增的实际剪枝及证明成本，再实施并验收。
