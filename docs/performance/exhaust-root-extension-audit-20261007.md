# 剪枝安全边界：真实根、事件与运行时扩展

本轮继续研究更合理的状态等价剪枝。真实猎手首领根的原生来源盘点和16个初始Fork检查通过，但尚未形成完整的耗尽顺序等价证书，因此没有启用新剪枝。本轮实际新增剪枝为0，没有整请求性能或峰值内存验收。[结构化证据](exhaust-root-extension-audit-20261007.json)保存临时源码、原始根清单、补丁记录、依赖入口及未验证项。

## 采用什么比较规则

已有完整合规胜利可以作为战损下界剪枝的见证；仍须使用经过认证的剩余回复上界，并遵守药水、成长、保命、遗物与资源追回目标。继续复用现有实现，不降低预算或修改评分。

新的优先方向是合并能够证明拥有相同后续行为的状态。候选投影只调整耗尽堆中已认证卡牌的不同类型分组顺序，保留完整卡牌指纹、同类型内部顺序、附着效果和其他堆顺序，以及现有历史、九条RNG与比较标签。保持这些字段还不够：必须证明所有可达读取、回调和扩展都无法区分被合并的顺序。

[既有只读诊断](exhaust-projection-subsets-20261007.md)中，限制回调类型的猎手根有76679次潜在准入、21482次潜在展开访问；这些是可能重叠的访问统计，不是已删除的独立分支，也不能推算提速。[原生正例](exhaust-positive-native-contract-20261007.md)仅验证了特定组件和动作；[原生反例](exhaust-equivalence-certification-20261007.md)已证明全局无序耗尽堆不安全。

生命支配暂列次优先级。[已有诊断](hp-state-dominance-research-20261007.md)显示机会较少；条件战后回复会破坏“较高生命一定更好”的单调关系。不能把回复总量上界证书当作生命支配证书。

## 发现的扩展入口

原生模块上实际记录875条Harmony补丁：817条来自`STS2-RitsuLib.Runtime`，58条来自CombatSolver。记录以类型/方法名标识，未保存重载签名、token、优先级及依赖模块自身的补丁，因此只是定位清单。875条不全影响战斗，也不能全部忽略或按程序集整体放行。

实际安装的RitsuLib运行时DLL SHA-256为`fe387f765a3951690b161c129731e6c10016215c06074aa3356dd96290f13b52`。本轮按此文件反编译核对如下入口，没有使用其他版本经验；其MVID及程序集版本未另行采集。

| 入口 | 实际调用链 | 剪枝证书仍需证明 |
| --- | --- | --- |
| 耗尽事件 | AfterCardExhausted后置桥接向RitsuLibFramework发布CardExhaustedEvent；框架依次通知typed handlers和通用observers | 捕获两套注册表及接收者状态；现有ModHelper订阅计数为0不能替代 |
| 监听器扩展 | ModelCapabilityHookListenerPatches扩展Run/Combat监听器 | 根能力、默认能力提供者、可达新模型的能力及注册变化 |
| 默认能力 | ModelCapabilityDefaults按OwnerType.IsAssignableFrom匹配注册，依Order及RegistrationOrder执行 | 不能只检查当前能力集合为空；还需匹配默认来源 |
| 克隆 | AbstractModel.MutableClone后置调用SavedData、Capabilities及CloneRegistry | 保存槽Clone、能力复制、按注册顺序执行的predicate/listener都属于回调来源 |
| 保存槽 | ModelSavedDataRegistry只在原型有bag时，按TargetType匹配槽并调用Clone | 需要原型bag和适用槽状态，不能把所有保存槽视作无影响 |
| 身份登记 | CombatState.AddCard后置登记牌、Affliction及Enchantment身份 | 单个登记方法未枚举牌堆，不代表身份后续消费者与顺序无关 |

现有空能力和免费出牌隔离补丁可以按其明确条件复用；SimulationNotificationIsolation本身只是作用域，不会自动屏蔽所有框架回调。此次没有扩大第三方内容支持面。

## 下一项可实施的证明

根捕获阶段建立不可变证书，纳入全部初始来源、可达生成闭包、事件接收者与适用扩展注册；后台只消费该证书和分支状态。未知来源、无法解析的回调、未认证的生成规则或注册变化应禁用这一新增等价剪枝，继续原搜索。

按读者实际依赖选择需要保持的顺序。不能仅将某张顺序敏感牌留在原位，就假设其他牌可任意重排；读者可能观察整个耗尽堆。必要时整根拒绝，只有证明读取范围后才缩小保序范围。卡牌变化、附着效果变化及生成均需维护资格，不能复用已失效的根条件。

完整原生/模拟差分、变更后的Fork与未知来源拒绝合同通过后，才接入转置比较并测量认证成本和实际剪枝量；最终候选再做固定根/政策/预算/DOP16的串行交错完整请求与峰值内存验收。本轮不报告新增两倍达标场景。
