# 公共回放与分支状态成本（2026-10-05）

剩余重场景应优先优化共同的分支状态处理。大量候选、长战斗和互补搜索成员放大同一管线；已支持的选牌续接并没有消除后续的分支复制、监听表维护和完整评估。本轮仅细分既有证据和核对源码，未修改运行时、启动新搜索或新增性能验收。

[结构化证据](common-replay-state-cost-20261005.json)记录七根选中solver的续接计数、同一份396张牌CPU trace的进一步归因及输入哈希。源码基点为 `4d2c9e0e`；实际原生模块仍为0.111.0、MVID `8a76776c-0ce1-4d4f-90bd-8cce653dad8e`、SHA256 `2b40d2df538db1ceb5fa48d958c80ab730ada1e07db88a870aff01a661768b9f`。

## 共性及范围

[整请求分析](heavy-scene-common-costs-20261005.md)已核对五根近期阶段结果：8～24个solver成员，主搜索用途只占12%～27%的请求耗时；精炼、开局能力及Smart成员均有实测质量贡献。不能删除这些成员或减少预算来达到速度门槛。

两份已有CPU样本的排他Snapshot/Replay/Fork合计分别为78.007%和88.786%。前者来自历史储君候选，后者来自最终开局准入DLL `e04003a5…` 的396张牌Evaluate诊断。它们提示公共管线优先级，不代表所有场景的CPU比例，也不是整请求提速空间的承诺。

完整快照同worker重复仅约1.126%，完整投影重复约1.9%／6.6%。已有测量不支持盲目缓存整份评估；跨worker／跨成员重复未测。应按字段依赖复用未变化部分，并保留原评分、浮点与整数累加、排序、牌序和RNG。

## 源码约束及通用优化优先级

1. **先减少监听表结构维护的重复扫描。** 现有[分支监听表](../../src/Search/SimulatedCombatState.cs)已经拆分Power／遗物前缀与卡牌／球后缀；卡牌移动、生成、变牌、附着变化和COW预览变更使后缀失效。[过滤器](../../src/Engine/Common/MirroredHookListenerFilter.cs)共享不可变类型布局，仍以完整类型次序确认复用。研究按这些真实变化维护布局／索引，保留原监听顺序、活动玩家／怪物过滤、补丁与未知来源回退；不能重复实现现有前缀拆分。
2. **再让评估按依赖变化复用。** [Snapshot](../../src/Search/CombatBeamSolver.StateEvaluation.cs)多次读取同一牌库来构建洗牌投影、牌库杂物、攻击保留值和战略上下文。复用现有卡牌／牌堆失效及Fork边界，先区分只依赖卡牌局部字段的特征与依赖全局回调／能量／敌人状态的特征。改变一个字段不能使未纳入依赖的评分或牌序缓存继续有效；未知依赖保持原计算。
3. **复制优化跟随实际分配和等待证据。** 已有[PredictedCard](../../src/Engine/Common/PredictedCard.cs)共享COW预览，wrapper的OwnerPile和观察者属于子分支，不能直接共享wrapper。[检查点](../../src/Prediction/CardChoiceContinuation.cs)加锁的Fork会暂时从seed移走pending选择，[执行续接](../../src/Engine/InCombat/Simulation/CombatPredictionSimulator.ExecutionContinuation.cs)也如此；直接取消锁会让并行分支读到被修改的seed。未测锁等待，DOP峰值16不能证明持续饱和，也不能据此认定锁是主要瓶颈。

三个方向按共同机制准入，用储君、亡灵选择密集根及猎手大牌组共同验证，避免按遭遇名实现。首先保留完整状态、Fork、RNG、父分支和live隔离；短搜有稳定收益才做串行交错完整Coordinator及最终固定回归。缓存有容量上限，只共享不可变元数据或具备严格分支依赖的结果。
