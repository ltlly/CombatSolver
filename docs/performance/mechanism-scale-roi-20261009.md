## 固定机制，仅改变牌量

使用当前实际安装的游戏 0.111.0，MVID `8a76776c-0ce1-4d4f-90bd-8cce653dad8e`、SHA256 `2b40d2df538db1ceb5fa48d958c80ab730ada1e07db88a870aff01a661768b9f`。冻结储君首领根有26张牌，向分支手牌加入一张防御，再向分支抽牌堆加入相同防御，得到27／128／396张。未改 live 或冻结根。

BenchmarkDotNet 0.15.8 的 InProcessNoEmit、MemoryDiagnoser、完整 JSON 和 DontRemove 控制测量；设置阶段预热缓存，测量中不手动循环，不启用 NoGC 或并行搜索。私有 Snapshot 预先绑定委托，避免把反射调用成本计入每次操作。每次 Fork 由当前父分支产生；检查父分支、根和 live 的续用戳。这些戳检查不替代完整原生状态差分。

## 以实际 JIT 检查底层假设

同一次独立诊断导出 StrategicEffectContext.Build 的实际 JIT：两份 Instrumented Tier0 和一份 Tier1。Tier0各有29个 Enum.HasFlag 调用位置、58个 NEWSFAST 位置；Tier1没有 HasFlag 调用、仍有9个 NEWSFAST 位置，并存在列表直接迭代与接口回退路径。

这些是静态调用位置数量，**不是每次操作的分配次数**。Tier1已消除部分高层调用，不能仅凭源码中的 HasFlag 推断应改汇编或换语言。本轮没有新增 PMU、CPU采样或底层改写；复用已有 CPU 证据和规模结果，优先试验未变化牌堆的监听候选索引复用。该运行时候选的原生、完整交错、质量及内存结论单独记录，不与本页微基准混用。

## 证据边界

三次早期构建失败分别为 SDK 属性导入顺序、BenchmarkRunner返回类型和 BenchmarkSwitcher集合类型；修正后六次作业全部成功。重复执行的72个形态案例不累计成更多独立案例。任务源码完整归档，临时诊断版 CardChoiceSupport 已按原字节恢复；实验构建关闭 CopyModOnBuild，没有部署这些微基准或索引探针。

尚未证明构造规模矩阵中的完整原生战斗等价、实际大选项集可达性、索引的整请求速度／峰值、DOP扩展或可见 Steam 性能。本轮未扩大用户接受的两个个别场景例外。
