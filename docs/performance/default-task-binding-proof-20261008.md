## 原生合同与保存范围

成功直接调用合同runId `030a7d4026724c7cadc72aca4d986d06`，Passed；请求26.2172815秒，启动器33.714034406秒。合同阶段37.9639ms包含反射、摘要、调用及作业等待，不是生产认证的热查询开销或性能验收。

所有98个默认定义直接调用后都返回同一已完成缓存Task。16个排队的worker作业分别调用98个定义，共1568次，同样通过；这不声明16条线程同时活跃。使用未初始化的原版DefendSilent和未被这些IL读取的占位参数，没有运行Hook分派、原生战斗动作或await收尾，也没有进行模拟/Fork/RNG/父分支差分。live的既有ContinuationStamp在前后保持，不宣称覆盖所有缓存和注册表字段。

首轮原生合同在调用这些定义之前失败：夹具误把缓存字段精确类型要求为Task，而实际类型为Task\<VoidTaskResult\>。本机9.0.20反编译正文帮助定位类型限制；它不是9.0.7游戏的来源证据。修正为当前游戏反射得到的精确泛型类型，同时保留readonly和缓存值检查后才运行成功合同。三次诊断Release构建14.14/14.27/14.62秒，各零警告/错误。

成功合同写到用户请求目录的自定义详细文件没有被启动器固定产物清单导出，并随实例清理丢失。结果文件仍保留Passed及合同源码中的断言范围。为保存真实模块、版本、hash/token和补丁信息，新增独立元数据采集runId `d69c85fff4f343da9a765a3729017ee8`，Passed，请求26.0590964秒、启动器33.535470067秒，采集阶段14.901ms；**这次没有调用98个默认定义，已通过行为合同沿用**。元数据写入明确任务产物路径并已归档，不补造丢失的第一次详细文件。

剩余13个默认虚方法的后续原生系数/输出参数证据见[独立报告](default-value-out-proof-20261008.md)；本报告保留Task依赖阶段的范围。
