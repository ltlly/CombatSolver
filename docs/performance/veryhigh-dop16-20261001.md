# 部分重战斗场景的搜索性能优化

[返回性能目录](README.md)

本次正式 PR 交付已保留的阶段成果，减少部分重场景中的回调扫描和重复搜索。原始任务仍要求所有基线超过20秒的场景至少加速2倍、峰值内存不增加超过10%、战损不增加；整个任务尚未完成。PR 整理在上游 `88298ae5` 上，不包含研究分支的撤回实验和约3.1%提速的伤害目标过滤原型。

## 改动范围

- 出牌续执行按普通／late阶段各自的参与位图捕获有序监听者。保留末击后的计数、阶段间重枚举、暂停与Fork重映射；未知模型和基类补丁继续走完整监听者路径。
- 请求预算中断时保留已经标注且符合政策的安全边界。
- 对审查过的原生卡牌、Power、遗物、药水和敌人来源证明剩余治疗上界。覆盖有限再生、静默毒／小刀牌组、`SOUL_NEXUS`，以及储君／`LOUSE_PROGENITOR_NORMAL`；未知来源继续使用保守上界。
- 只把符合硬政策的完整无药胜利共享给组合成员作为战损界。提前运行既有开局计划和回合边界续搜，沿用共享预算与候选上限。
- 只有初始治疗上界为零、完整无风险满血零损胜利、无成长／遗物目标、无保命资源消耗且满足药水要求时，才能提前结束可选药水后验审计。

搜索预算、并行度和NoGC配置均未降低或扩大。新增的根治疗元数据不可变；没有新增分支可变状态。

## 配置和测量口径

Ryzen 7 7840H，8核16线程，Linux，.NET SDK 9.0.120／CLR 9.0.19，游戏0.111.0及对应RitsuLib。固定极高预设：Beam135、节点500000、出牌／牌堆选择／手牌选择分支72／42／54、并行度16；完整协调器与组合成员、原场景药水政策、请求预算300000毫秒、非FixedBudget、NoGC配置16GB。

请求墙钟包含搜索内GC生命周期；不含建局。正常请求时间帽不等于包括后置成员和回收的严格进程上限。峰值为操作系统进程高水位，包含建局与采样间峰值。所有正式ABBA顺序运行，未与本任务构建、诊断或其他搜索重叠。Linux离线耗时不外推可见游戏帧时间、FPS或Windows收益。

比较完整保存质量、风险、胜负、战损、药水与其他政策字段；仅允许结束回合及分数变化。Passed只表示宿主完成，时间边界仍单独记录。原生合同承担模拟正确性验证，离线报告不能代替原生差分、严格增量或部署验证。

## 当前上游回归的质量差异

`dev-09-necrobinder-boss` 首个配对样本中，上游45.550秒、战损17、1瓶药／战略药水成本70；PR版本25.326秒、战损0、2瓶药／成本115。两侧均胜利、存活、无风险、无保命资源消耗、无时间边界，峰值比0.5736。该样本的战损没有退化，但严格逐字段检查不允许药水成本或数量增加，因此仍记录为质量门槛未通过。

源码 `RouteQualityPolicy.ComparePrimary` 的终局主排序优先比较胜负、保命资源消耗和战略战损，`PotionPolicy` 投影再使用该排序；`Interim` 投影另外比较资源总负担，两者口径不同。更低战损不能让本批严格逐字段门槛自动通过；完整配对、重复样本和原生证据仍需继续，验收工具保持原门槛。


`screen-queen` 首个完整配置配对也未通过质量门槛：两侧都触发时间边界，上游 311.168 秒取得第 13 回合完整胜利（战损 67、敌方 HP 0），PR 版本 302.265 秒仅得到存活的未完成路线（战损 22、敌方 HP 557）。较低的未完成路线战损不能抵消完整胜利缺失。原生根和配置匹配；上游首个 `ENTROPY` 能力开局成员找到胜利，候选同成员到达时间边界；该遭遇没有运行提前开局 incumbent。重复稳定性和根因尚未确认，合并前必须解决。 详细数值见[女王失败样本](veryhigh-dop16-queen-screen-failure-20261002.json)。
