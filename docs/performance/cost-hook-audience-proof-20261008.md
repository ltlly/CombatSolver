## 本轮能力缓存的原生证据

当前生产PredictionRitsuCapabilityAudit检查现存宿主的活动能力和未知保存条目，未直接检查两个内部快照。实际ModelCapabilitySet.GetOwnerHookCandidateSnapshot会复用缓存数组；GetOwnerHookCapabilities随后先执行ShouldReceiveOwnerHooks，再按返回值筛选。只有筛选通过后才判断Owner及插入受众，故最终列表不变不表示调用无副作用。

原生`21f87a4f7acb4f54a07f6ebf221f3d3b` Passed，请求26.099秒；这包含建局和断言，不是完整Coordinator时间。复用故障机器人精英生成根，未启动搜索。

| 验证 | 实际结果 |
|---|---|
| 原生API附加、物化候选、移除 | 活动列表归零，两个快照均清空；筛选getter未调用 |
| 反射只向候选快照注入能力 | 活动列表0、未知保存条目0、候选1，当前生产检查接纳 |
| 直接调用实际ExpandOwnerHookListeners | 仅返回原规范防御牌，受众身份/长度保持；false筛选getter调用1次 |
| getter原生生命写入 | 玩家60→62；反例刻意造成实机回复，不是actual/simulated相等 |
| 旧父分支及一次子Fork | 完整预测状态、历史和RNG保持 |

能力对象由ModelDb原型的原生MutableClone取得，持久化槽和能力在初始化期登记。保存并恢复两个快照、能力Owner及原无能力标记；独立实例自动删除。玩家HP的两点变化属于反例本身，没有声称live全状态保持，也未验证16路性能或并发Fork。

正常原生增删、清空、载入和复制路径调用InvalidateAttachedSnapshot；该方法清空两个快照并删除无能力标记。本轮直接验证附加/移除，其余是同版本源码证据。**没有证明普通API能产生该失配状态，没有实际错误剪枝或玩家故障复现。** 不据此增加生产反射检查；审计过的原方法、无额外补丁、遵守API及单线程一致性是这项局部论证的前提。未知补丁、反射修改或后续动态变更另行拒绝/审计，不能把这项前提当作完整生命来源证书。
