## 先证明哪些顺序不能忽略

定向复核既有原生反编译来源及同版本方法/委托引用清单，没有重新扫描DLL。清单定位到11处`get_ExhaustPile`引用，还需沿`PileType.GetPile`、`CardPile.GetCards`、`PlayerCombatState.AllCards`及回调继续追踪；它不是字段、虚调用和递归生成的完整证明。

| 已定位来源 | 原生及当前模拟行为 | 对等价证明的约束 |
|---|---|---|
| `Eidolon.OnPlay` | 按消耗堆顺序筛选可打出的虚无牌并自动出牌 | 保留执行顺序；原生`CanBeGeneratedInCombat=false`，初始持有、复制、回收仍单独检查 |
| `KnifeTrap.OnPlay` | 按堆内顺序自动打出小刀；升级及首次播放标志逐实例结算 | 小刀同名不代表费用、升级、重复执行和附着状态相同 |
| `Bombardment`及`HowlFromBeyond` | 回合阶段触发或离开消耗堆后自动出牌 | 已消耗不代表永久不会再执行 |
| 原生`AllCards`及监听接收者 | 遍历各有序牌堆；当前模拟监听维护也保留该顺序 | 没有直接取牌命令仍可能有顺序敏感回调 |
| 待返回牌、注册模型引用 | 当前完整指纹保存所属牌堆位置；原生/模拟模型状态可引用具体实例 | 不可把这些位置或身份关系一起删掉 |

这些是已定位风险，**尚未形成任何新安全认证**。不能根据角色、原版程序集、当前没有回收牌、回复来源少或拥有Exhaust关键字默认安全。

## 更合理的实现方向

**保留完整状态键，另建经过认证的搜索等价键。** 当前Beam的同分排序会比较原StateKey两部分；直接打开mask8会同时改变排序数值。独立等价键可让新规则只进入转置查找，保持原键用于Beam排序、续用、诊断和严格状态对账。它仍会改变保留集合，必须单独验收决策质量。

认证按机制和可达来源组成，逐项正向证明消耗牌不会因排列改变未来合法动作、生命/资源/成长目标、RNG、模型回调、具体实例引用或原搜索租约。必须覆盖全部初始牌堆、待返回牌、生成池的原生过滤/解锁/玩家人数、复制/变牌/回收和附着来源。未知返回原有序键；已经安全审计的组件才逐步扩展，不能用黑名单缺席作默认认证。根只冻结不可变来源资格，分支状态和有效机制仍由分支拥有。

若只有部分消耗牌可证明永久无交互，则保留其他牌及顺序敏感来源的原序与引用，再对已认证部分建立投影。这个分解本轮尚未实现或证明；不能把已认证回复组件当作已认证顺序组件。

继续保留原六项支配、循环/有序变异租约和所有胜利/战损/成长/药水/遗物/追回/复活/首领比较。已有回复上界仍仅消费完整合规胜利，并只否证严格更差的可达结果。相等HP、不同历史、不同资源目标或不同成员政策没有新证明时继续搜索。

下一阶段先完成投影组件的原生可达闭包和最小完整状态/Fork/RNG/父/live差分，再接入实际剪枝，统计真实减少的Replay/Snapshot及认证开销；之后才做串行交错整请求和最终固定回归。不能从本轮15%左右的猎手展开入口机会推导2倍提速。
