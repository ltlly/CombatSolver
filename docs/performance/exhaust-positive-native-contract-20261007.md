每次按表中手牌顺序出牌。每个动作先分别推进原始及反向消耗顺序的模拟，再通过真实`PlayCardAction`执行原生动作。模拟两排列的完整状态文本、原键、富历史、九路RNG及洗牌计数、终局标记归一化后相等；原生与自身模拟的完整状态和既有严格快照相等。四次出牌后手牌数依次为3、2、6、8，也覆盖未来生成普通Shiv及Inky Shiv。

每实例从四次原生出牌后的新根模拟EndTurn，再执行真实EndTurn到回合2，原生完整状态/RNG与自身模拟相等。两实例的归一化初始状态、四个动作检查点及回合2状态哈希相同；原生未归一化的末状态哈希不同，保留消耗顺序差异。两者均为HP58/MaxHP70、战斗未结束。

**跨回合范围：** 每个实例内反向顺序的影子分支比较到四次出牌；EndTurn比较新根模拟与该实例原生，最后另外比较两实例的归一化末状态。没有在每个实例内额外执行反向影子的EndTurn。原生动作历史没有逐条与富模拟历史差分。

## 更正确的剪枝设计

现有严格战损剪枝依赖完整合规胜利和保守回复上界，继续保留其政策门禁。新的等价剪枝应满足另一种证明：两分支的所有合法后续动作能对应，结算、RNG和目标比较一致，才允许沿现有支配规则删除一个。

| 必须保留或证明的部分 | 原因 / 后续实现边界 |
| --- | --- |
| 同类内部顺序、附着牌及未知牌位置 | 同一类型不同状态也可能影响选择和回调；固定槽位本身不能证明跨类型交换安全。 |
| 原始完整键用于排名 | 归一化只用于经过认证的转置查询，避免同时改变Beam排序。 |
| 原六项支配标签及租约旁路 | 不把键相等变成无条件删路；药水成本、战损、动作数和分数仍按原规则比较。 |
| 初始及可达来源的正向证书 | 核对全部牌堆、消耗堆、待返回牌、floating/private来源及永久牌组；未知来源立即旁路。 |
| 生成池和未来附着效果闭包 | 复用已审计的原生过滤前提，逐组件递归；初始牌安全不代表未来生成牌安全。 |
| 基类事件、实际虚槽和补丁 | 没有声明Hook、原版程序集身份、订阅数量为零都不足以证明不观察顺序。 |
| 根不可变元数据和分支拥有状态 | 不读取变化中的live，不在Fork间共享可变认证结果。 |

推荐先把这些条件做成按组件组合的正向证书，并明确每个拒绝原因，再接入真实转置表。本轮正例及已有反例分别作为允许和拒绝路径的材料；不能由几个相等检查点推出所有合法未来相等。
