## 保留的门禁

`PredictionRitsuCapabilityAudit.Validate` 在稳定主线程根捕获和live采用边界执行：

- 核对上述 Runtime/Shared 的实际MVID和已审计字段布局。模块身份限定适用版本，不能单独证明语义。
- 在原生注册锁内读取默认能力修正列表；任何未支持的默认注入都明确失败，即使当前对象尚无能力。不调用其工厂。
- 遍历已存在的 ConditionalWeakTable，包含当前模型和可能以后被复制/生成的规范原型。直接读已审计 Box 与列表字段，不创建附着宿主，不读能力的Owner/ID属性或调用能力。
- 非空能力列表或未识别保存条目均明确失败。不会将Count为0、暂时未激活的未知来源认证为安全。

缓存只保存反射元数据；检查不保存模型、弱表枚举结果或可变资格。Fork和后台不新增这些检查，使用已冻结根及分支状态。注册空能力工厂、空宿主仍可正常认证。由于未知附着行为没有镜像，门禁保守地拒绝任何现存非空宿主，可能包含本场不可达对象；没有据此实现第三方内容适配。

本项仍没有形成所有回复来源封闭证明。其他Ritsu全局生命周期监听、模型接口提供者、命令与回调补丁、生成/复制/回收全闭包及其他生命值写入仍需逐项审计。搜索运行期间外部动态修改能力定义后，worker原生克隆的隔离尚未认证；不能把根/live拒绝外推成这项保证。
