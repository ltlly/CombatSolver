模拟没有执行live回调；原生推进后，冻结父分支完整状态、历史及RNG保持。finally仅移除本夹具的控件并排队释放。Passed表示**反例复现**，不能当作原生/模拟状态等价、实际错误剪枝或完整获胜路线验证。

## 保守准入原型

一次性 `TaskHealthSourceAdmission` 在主线程逐Creature读取当前/最大生命事件，检查精确方法、实际目标类型/Tracker身份、审计MVID及相关补丁组合。只读取字段和注册内容，不执行监听器、生成工厂、选择谓词或详情回调。已观察到的界面方法仅用于继续追踪；识别它们不代表认证安全。

Tracker转发检查自己的战斗状态身份和嵌套监听器；Ritsu分支检查当前页面、目标玩家序列、实际浏览器后代及详情控件的确切 `List<Action>`。原型对生命setter、内部生命方法、转发、重算和已检查的监听入口补丁明确记录拒绝。结果中的拒绝列表采用不可变数组，worker只消费冻结结果。

| 断言 | 明确拒绝原因 |
| --- | --- |
| 普通原生通知根 | 原生UI、Ritsu UI和卡值重算的完整调用/信号链未证明 |
| 玩家当前生命未知监听 | `direct:CurrentHpChanged` |
| 玩家最大生命未知监听 | `direct:MaxHpChanged` |
| 敌方当前生命未知监听 | `direct:CurrentHpChanged`，保留具体Creature身份 |
| 未知Tracker监听 | `tracker:…` |
| 外层方法不变、内部详情新增回调 | `ritsu-detail-callbacks:1` |
| 未知生命setter补丁 | 具体setter补丁 |
| 未知通知转发补丁 | `patch:tracker-notify` |
| 未知卡值重算补丁 | 具体重算方法补丁 |

每组分别调用两次准入验证，模拟拟接入的根与live采用检查位置；**生产 `CombatRootSnapshot` / `ContinuationStamp` 没有接线**。这不是已完成的正式根/live拒绝修复。

九组断言通过，未知回调和补丁函数的实际调用次数为0。串行预创建16个孩子，在live新增监听后并行比较其完整状态/历史/RNG及各自下一代Fork；父分支和live保持，清理后拒绝列表恢复。该合同没有在孩子中推进战斗动作，也不是并发调用父状态的Fork。

准入夹具保留原包药水，记录的原组件剪枝资格为false；回复反例则清空药水，资格为true。不能将两份输入的根资格混为一项阳性认证。新增完整来源证书覆盖为 **0/1普通通知根**，普通根仍被三项未闭包原因拒绝。恢复后盘点直接事件7次回调绑定、Tracker8个实例、浏览器24个节点，详情回调0；这些数量只表示本次实际根。

## 为什么仍不授予证书

已核对的下层路径继续暴露证明义务：

- 原生手牌通知会在选择模式执行 `_currentSelectionFilter`，并可能完成选择Task。当前没有选择谓词不证明未来所有选择来源安全。
- Tracker通知前调用 `PlayerCombatState.RecalculateCardValues`，继而调用附魔的重算入口。需要沿实际附着和未来来源检查。
- Ritsu默认页面在目标玩家或ID序列改变时会走页面/浏览器重建；其他页面涉及牌堆、怪物及次级资源。空页面表不能替代这些可达路径证明。
- `RefreshCreaturePickButton` 的文字自适应来自独立的Ritsu UI程序集，读取Font、StyleBox等资源并写主题字号。现有UI扫描没有直接生命命令引用，但虚调用、Godot信号和方法以下补丁还需独立闭包，不能由“0个Heal引用”认定安全。
- CubexConstruct的生命监听、悬停提示、首领背景等其他入口单独保留审计范围。未来生成/召唤、延迟async状态机和新注册来源仍未闭合。

因此没有把普通界面名称、原版程序集身份或非gameplay清单升级为默认安全规则，也没有把“详情回调为空”单独写成充分条件。

## 对剪枝设计的影响与交付范围

继续采用上一轮已经证明的 `R + min(T, maxHp-hp+G)`，其中 `T` 与 `G` 都要求完整可达来源证明；生命周期、次数、重复/复制/回收、合法药水顺序及其他目标另由现有政策判断。当前缺血与未来增加的生命容量应共同计算，避免将满血果汁等来源错误裁成0。

接入顺序应先证明通知来源，再冻结根资格并在live采用时重查动态注册，最后让分支拥有的回复/容量状态消费已保留完整胜利。只有严格更差战损才能剪，相等战损及无法证明成长、遗物、药水、追回或保命目标的分支继续原搜索。组件类型表通过与完整来源证书、阶段调度资格各自保持明确边界。

本轮正式业务源码不变，生产新增剪枝0、生产未知来源拒绝修复0。没有纯性能对照、认证独立开销、整场质量/药水/回合/峰值验收或最终固定回归，也没有新增两倍达标场景。原始魂枢包恢复和历史战损缺口继续保留。

一次性源码、路由、props及启动器先归档，再清理；Executor按原字节恢复。正式Release/结构/工具/覆盖门禁及本地五文件部署复用704dc994同源码的成功证据，只重跑改动文档的门禁。没有创建PR、自动合并、提升版本、发布或启动可见Steam。
