# 卡值重算通知的条件子证明（2026-10-08）

**现有三种已审计附魔的直接重算可以形成较窄的子证明，仍不能授予完整生命事件证书。** 本轮沿[上一轮准入研究](health-event-source-admission-20261008.md)的实际Tracker通知链检查 `PlayerCombatState.RecalculateCardValues`。原生合同通过五牌堆准入、三种空方法绑定、一次直接重算、九类未知来源的18次拒绝及16个冻结分支；未修改生产。[配套记录](card-value-notification-proof-20261008.json)保存源码、原始结果、输入、调用引用和失败记录。

## 版本与直接调用链

继续 `perf/common-state-cost-20261005` / `56ddc6f1`，正式运行时仍为 `704dc994`。上一轮完成的原生嵌套回调反例与保守拒绝实验属于进展，下一动作据此收窄到卡值重算，而不是重新测试所有来源。

游戏 `0.111.0 / 41cef1ea`、MVID `8a76776c-0ce1-4d4f-90bd-8cce653dad8e`；Ritsu Runtime `0.6.6`、MVID `f7f18a36-8ebb-4db2-b1ea-7bd340579646`。完整哈希沿已有直接证据复用。实际原生宿主仍为CLR9.0.7。

当前DLL的调用链为：

`RecalculateCardValues` → `AllCards` → `AllPiles.SelectMany(pile => pile.Cards)` → 每张牌的 `Enchantment` → `RecalculateValues`。

原版 `AllPiles` 缓存按手牌、抽牌、弃牌、消耗、出牌堆排列的五个 `CardPile`；`Cards` 直接返回具体 `List<CardModel>`，`Enchantment` 是非虚自动属性。没有额外Hook门面或默认完成通知包在该直接调用外层。

当前游戏全量IL清单只有基础附魔与 `Adroit` 声明 `RecalculateValues`。基础方法体是单条 `ret`；`Adroit` 覆写为设置自身Block变量，不能从没有Heal引用推断整个动态变量链安全。本轮只接受现有严格回复表已列出的 `Slither`、`Inky`、`Instinct`，逐项核对它们绑定基础定义的模块、token、声明类型及空方法体，没有由原版程序集身份扩大全部附魔覆盖。

## 条件与拒绝

一次性 `TaskCardValueNotificationProof` 只在主线程检查当前子链，条件包括：

- 原生与Ritsu审计版本匹配；重算、牌枚举、牌堆Cards及附魔getter没有未知补丁。
- Ritsu `AllPiles` 只存在实际核对的唯一后置补丁；注册表已冻结，具体战斗定义数组为空，转发方法无未知补丁。复用[原生牌堆证据](exhaust-root-turn-contract-20261008.md)的原前提，并再次读取当前实例与快照，而不缓存可变注册值。
- 当前 `_piles` 缓存只能为空或与五个原生牌堆引用和顺序完全相同；每个牌堆必须是确切原生类型和具体List，卡牌引用不能同时属于多个牌堆。
- 只允许三种精确附魔类型，未来绑定检查也仅指这三种类型继承空定义。其他当前附魔、未知牌堆及变更的getter/重算补丁拒绝。
- 当前原型检查PCS嵌套枚举辅助和LINQ程序集的补丁边界；标准库枚举依赖实际原生CLR/LINQ语义。**这不是任意CoreLib补丁的通用审计**，完整证明仍需保持这一前提或补齐更低层组合检查。

`Result.Certified=true` 的含义仅是上述条件检查通过。不能将其当作全部生命事件、未来生成来源或整根回复闭包的证书。未知来源拒绝不执行其getter、覆写、回调、牌堆工厂或补丁函数。
