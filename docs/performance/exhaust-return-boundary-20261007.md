## 合同覆盖

两张真实出牌建立历史资格；连续模拟与逐步Fork模拟均匹配实际移动。新根导入已完成出牌历史，正序和倒序自有影子分支分别解析回手，末位手牌不同，完整续执行状态及富历史不同。

每组从未变的父分支串行Fork16个孩子，再并行执行回手；16个结果与参考完整状态/历史一致，逐一检查孙分支保持一致。两次父/live隔离检查通过。原生随后执行隔离的下一玩家回合BeforeHandDraw与回合开始回调，完整ContinuationStamp（含RNG）及移动快照与正序模拟一致。没有并发Fork同一可变父分支。

这里直接推进测试回合并调用原生Hook，没有执行敌人回合、完整抽牌、自动出牌阶段或Coordinator。原生完整状态与模拟比较，富历史在模拟分支间比较；不能推成所有原生历史字段及所有未来动作等价。两个原生结果均为回合2、生命56/70，战斗未结束。

## 更合理的剪枝条件

1. **战损界与状态等价分别证明。** 完整合规胜利提供已有界，保守的剩余回复量只允许淘汰严格无法达到该界的路线；回复量相同不能证明后续行为相同。成长、药水、保命、遗物和资源追回目标仍遵守已有比较规则。
2. **保留会影响后续动作的顺序。** `PrepareBeforeHandDraw`从有序AllCards筛选回手资格，不按资格HashSet枚举。手牌容量会把后到的牌送进弃牌堆。现有生命周期指纹还编码待回手牌的牌堆位置，本次倒序并未证明生产键相同，不能据此声称现有转置表发生碰撞。
3. **审计实际观察链。** 两张牌通过Card.Pile检查当前所在牌堆，再调用CardPileCmd.Add；并不需要直接调用get_ExhaustPile。只检索消耗堆字段会漏掉观察者。记录中的无色牌池引用也是来源候选，实际可达性仍需具体生成入口、解锁与过滤的闭包证明。
4. **已有安全条件不重复放宽。** `RemainingHealingUpperBound`逐张拒绝未认证的待回手类型或附着效果；已认证的ThrummingHatchet保留零回复证明。组件根/分支认证同样逐张覆盖待回手牌。既有原生合同已经检查Hatchet跨Fork零回复，以及未审计离堆Bolas保守未知，直接复用，未重跑。

因此，本轮纠正了“有待回手牌就整体放弃回复证明”的研究假设；没有发现可以据此提速的现存整体门禁。可以复用容量合同约束后续等价证明，未知观察者、未知写入及未封闭未来来源继续保留原搜索。
