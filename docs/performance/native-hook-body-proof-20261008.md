# 原生默认回调的方法体证明

本阶段把“模型没有覆写回调”的元数据线索推进到实际默认方法体证据。工具新增定义身份、原始 IL 摘要和完整指令；**没有授予新的搜索认证，没有新增实际剪枝或提速验收**。常量返回是否中性取决于调用方，默认实现之后的事件和活动补丁仍需证明。

结构化结果、全部方法体、一次性夹具源码和检查结果见 [JSON](native-hook-body-proof-20261008.json)。源码基于 `5dbae7ca`；生产 Mod 保持 `36370e54`，已成功部署的同源码 DLL 沿用 [模型能力回复证明](model-capability-recovery-proof-20261007.md) 的证据，不重复构建或部署。

## 输入与范围

输入为实际安装的游戏 `0.111.0 / 41cef1ea` 的 `sts2.dll`，SHA-256 为 `2b40d2df538db1ceb5fa48d958c80ab730ada1e07db88a870aff01a661768b9f`，MVID 为 `8a76776c-0ce1-4d4f-90bd-8cce653dad8e`。工具只读取文件，不加载或执行游戏。

`HealingSourceAudit` schema8 读取 Hook 直接引用的 180 个模型入口定义，包含 179 个虚方法及非虚 `InvokeExecutionFinished`，也包含战斗外入口。因此这个数量既不是战斗监听者数，也不是认证覆盖率。同文本定义按 MVID/MethodDef token 分别保留；调用操作数可能是 MemberRef/MethodSpec，不能冒充已解析目标定义。

schema7 原有 37 个负载字段保持相同，限制说明原有内容保持。该增量不需要重新扫描输入未变化的依赖 DLL。此前静默猎手首领初始及明确生成的 20 类牌未声明这些 Hook 或克隆/创建/反序列化覆写的证据按原前提复用；这不证明全部未来来源或整个回调顺序安全。

## 方法体证据

| 形状 | 定义数量 | 可以支持的结论 |
| --- | ---: | --- |
| 返回形式参数 | 30 | 无其他指令；参数与返回类型及作用域一致，尚需核对调用方 |
| 整数或布尔常量 | 36 | 无其他指令；常量不自动等于调用方的中性值 |
| 空 void | 2 | 定义内只有 `ret`；调用后的事件、补丁另审计 |
| 无参数静态调用后返回 | 98 | 都调用 `Task.get_CompletedTask`，依赖绑定及补丁未解析 |
| 未分类 | 14 | 保持未知，不授予资格 |

68 个定义的简单结果有直接指令证据。98 个外部调用不能与它们合并为已证明纯方法；未分类的 14 个定义包括 6 个 Decimal 静态字段读取、1 个 Decimal 构造、6 个输出参数写入和事件分派入口。字段、构造和输出参数可能有可证明的语义，但本阶段不猜测。

分类器拒绝额外指令、分支、局部变量、异常区域、未解析泛型、返回接收者、byref 别名及不同作用域的同名类型。外部调用只保留形状和证据，不作纯度认证。原始 PE 与 Cecil 模块身份不一致时失败，原始 IL 摘要与解码指令均保留。

## 验证与限制

工具 Release 构建最终 2.16 秒，零警告/错误；首轮命名空间冲突编译失败已修正，失败前没有运行扫描或夹具。一次游戏扫描产出上述 180 项。

47 项元数据检查通过：复用夹具重新穿过改动后的工具入口，覆盖 9 项虚槽、5 项签名歧义/token 和 7 项事件候选；新增 21 项方法体形状边界和 5 项原始 PE 身份/摘要检查。同文本普通/泛型方法都保留，独立指定的原始 IL 字节摘要匹配。刻意有副作用的静态 getter 仍只能归为“未解析调用”，不能取得安全资格。

夹具构建成功，有一项 `MSB3539` 警告，来自一次性项目在 SDK props 之后显式导入工具 props；产物保持在 `.local`。部分夹具故意包含 CLR 不可验证的签名/IL，因此这些是元数据工具合同，不是原生战斗、完整状态、Fork、RNG 或隔离测试。夹具源码归档后清理；原始扫描与检查产物保留。文档、工具和覆盖目录门禁结果记录在 JSON。

本阶段新增根认证 0、实际额外剪枝 0、游戏合同 0、性能请求 0。没有修改生产语义、评分、预算或部署 DLL，也没有增加两倍达标场景。

## 剪枝仍需的证明

先按实际 Hook 的聚合、早退和遍历规则证明每个默认返回值的作用，再核对外部调用、活动补丁、`InvokeExecutionFinished` 委托、生命周期包装及监听者 getter。已有 [消耗顺序反例](exhaust-equivalence-certification-20261007.md) 和 [有条件原生正例](exhaust-positive-native-contract-20261007.md) 保持各自范围，不能从局部正例放宽全局转置键。

初始、生成、复制、回收、附着及私有来源必须形成未来闭包；资格应由稳定根和分支自有状态消费，并在相关状态变化时失效。完整闭包、运行时消费者、原生/Fork/RNG/live 合同及纯串行交错性能均尚未实现。当前证据用于继续收窄证明对象，不能以“原版默认方法”或“本场景没有覆写”替代这些条件。
