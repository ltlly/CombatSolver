# 静态牌值公共缓存研究（2026-10-06）

原型撤回。三根完整Coordinator交错中，大牌组约1.047倍、亡灵首领约1.022倍、储君基本不变；最终固定回归出现峰值内存超过10%门槛。因此不提交运行时优化，不把局部收益当作两倍目标完成。逐次结果、来源与失败见[结构化记录](intrinsic-card-value-research-20261006.json)。

## 版本、语义与所有者

以合入PR #213的`bb004176`／上游`9a4489d8`、CombatSolver 0.50.0为基线。实际游戏0.111.0的DLL SHA256为`2b40d2df538db1ceb5fa48d958c80ab730ada1e07db88a870aff01a661768b9f`，MVID为`8a76776c-0ce1-4d4f-90bd-8cce653dad8e`。Ryzen 7 7840H（8核16线程）、约58GiB内存，离线宿主CoreCLR 9.0.19；原生合同宿主9.0.7、Ritsu 0.6.5。

定向反编译实际DLL，确认DynamicVar.BaseValue为非virtual字段读取，CardModel.DynamicVars为卡牌局部集合的惰性初始化。集合成员只由构造器建立，没有公共增添或替换入口；基础数值仍会写入和升级。牌型getter为virtual，继续每次读取，不缓存。公式及浮点顺序保持：Damage基础值＋Block基础值×0.8＋Cards基础值×3，再加当前Power牌型的8分。原CardModel公式保留作独立oracle。

根捕获冻结审计模块、两项getter的Harmony补丁权限及来源资格：无BaseLib卡牌修饰器、无已捕获run/combat订阅者，卡及已有附件属于审计模块。PredictedCard仅在已共享、已物化的预览COW存储中新增8字节标量；可写预览不缓存，持有同一可写引用连续修改也重算。COW和显式失效清空，Clone新建，Fork共享不变预览的结果。不透明、未知及不符合资格的来源回退原公式；没有修改评分、预算、药水或成长政策。

首版原生603类型合同通过后，源码审查发现未共享预览可能被保留引用继续写入；加强为SharedOnly后才做性能筛查。SharedOnly初筛后扩大搜索、起手和能力估值等调用点，最终候选DLL为`36caae2059f331509c64e031deaa9ac0f6283d84bcb74f001238fef337a785f0`。这些是公共牌值计算成本优化，没有新增回复上界证书。
